# Посібник адміністратора та власника

## Межі відповідальності

Адміністратор/власник обслуговує Telegram-бота, локальне середовище Python, секрети, SQLite-базу та налаштування доступу. Якщо потрібно, він призначає модераторів і адміністраторів підтримки. Це окрема роль від редакторської перевірки курсу.

Технічні адміністратори не мають окремих команд у меню бота. Адміністратор підтримки — це адресат звернень, визначений у `SUPPORT_ADMIN_IDS`; наявність цього ID сама по собі не надає прав модератора.

## Перший запуск Windows

Потрібні Python 3.12+, доступ до інтернету, Telegram-бот від BotFather і PowerShell. З теки проєкту виконайте:

```powershell
py -3.12 -m venv .venv312
.\.venv312\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
Copy-Item .env.example .env
notepad .env
```

У `.env` заповніть щонайменше:

```dotenv
BOT_TOKEN=токен_від_BotFather
ALLOWED_USER_IDS=123456789
MODERATOR_IDS=123456789
SUPPORT_ADMIN_IDS=123456789
```

Усі значення ID — числові Telegram ID; кілька ID розділяються комами. Токен отримайте через `@BotFather` і зберігайте лише в `.env`. Не публікуйте його в чатах, логах, скриншотах, issue або репозиторії. Файл `.env` і каталоги `data/`, `logs/` ігноруються Git.

Запустіть:

```powershell
.\start_bot.ps1
```

Залиште вікно відкритим. Зупинка — `Ctrl+C`. Якщо Windows забороняє виконання скрипту, можна дозволити запуск лише в поточному процесі PowerShell:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\start_bot.ps1
```

Цей режим запуску локальний і безкоштовний, але бот працює лише поки комп'ютер увімкнений, не спить, має інтернет і процес активний. Вхідні оновлення отримуються через Telegram long polling; відкривати вхідні порти не потрібно.

## Доступ і ролі

| Змінна | Призначення |
|---|---|
| `ALLOWED_USER_IDS` | Глобальне обмеження доступу до обробників бота. Заповнений список дозволяє тільки ці ID; порожній рядок означає, що обмеження немає. |
| `MODERATOR_IDS` | Дозволяє використовувати `/admin_import`, `/admin_pending` і `/admin_approve`. |
| `SUPPORT_ADMIN_IDS` | Telegram ID, яким бот пересилає текст звернень через `/support` разом з ID автора. |

Для приватного тестування залиште в `ALLOWED_USER_IDS` тільки власний ID. Щоб запросити інших тестувальників, додайте їхні ID через кому, наприклад `ALLOWED_USER_IDS=123456789,987654321`; не залишайте поле порожнім, якщо хочете обмежений тест. Після редагування `.env` перезапустіть процес: активна конфігурація сама не оновлюється.

`MODERATOR_IDS` не змінює доступ учнів, коли немає allowlist. І навпаки: якщо `ALLOWED_USER_IDS` заповнений, ID поза списком не зможе виконувати й команди модератора.

## Налаштування та шляхи

| Змінна | Типове значення | Опис |
|---|---|---|
| `DATABASE_PATH` | `data/bot.sqlite3` | Активна база профілів, прогресу, курсів і технічних подій. |
| `LOG_PATH` | `logs/bot.log` | Файл журналу; додатково повідомлення пишуться в консоль. |
| `INACTIVE_PROFILE_MONTHS` | `12` | Строк бездіяльності до видалення профілю. |
| `TECHNICAL_LOG_RETENTION_DAYS` | `30` | Строк зберігання технічних подій і кількість ротацій журналу. |
| `VOCABULARY_PASS_THRESHOLD` | `0.7` | Мінімальна частка правильних відповідей у повторному тесті. |
| `REMINDER_POLL_SECONDS` | `30` | Інтервал перевірки нагадувань, мінімум 5 секунд. |

12 місяців і 30 днів — початкові запропоновані значення, а не підтверджена політика. Власник має затвердити строки з урахуванням реального використання. Заповніть контактні та інші поля у [privacy-policy.md](../privacy-policy.md), перш ніж розширювати доступ. Не заявляйте юридичну відповідність без окремої перевірки.

## Запуск, оновлення і перевірка

- Звичайний запуск: `.\start_bot.ps1`.
- Перевірка контенту й локальних потоків SQLite: `.\.venv312\Scripts\python.exe -m telegram_bot.main --check`.
- Тести: `.\.venv312\Scripts\python.exe -m pytest`.
- Створити окрему SQLite-базу лише з курсами: `.\.venv312\Scripts\python.exe -m telegram_bot.main --init-content-db`.
- Переглянути її: `.\.venv312\Scripts\python.exe -m telegram_bot.main --inspect-content-db`.

Під час запуску застосунок ініціалізує схему та завантажує курси з `content/courses.json`. Якщо курс має лише одну початкову опубліковану версію (v1), зміни вбудованого курсу створюють нову опубліковану версію; прогрес учнів не видаляється. Якщо курс уже має додаткові/модераторські версії або чернетки, автозаміна не виконується — для контрольованої редакції використовуйте модераторський імпорт і затвердження. Не видаляйте активну базу, щоб «оновити» матеріали, якщо в ній є профілі чи прогрес.

## Відкриті дані для тренажера

Після перевірки актуальних умов у першоджерелах завантажте дозволені матеріали та зберіть окрему пошукову базу:

```powershell
.\scripts\download_cefr_datasets.ps1
.\.venv312\Scripts\python.exe scripts\build_open_dataset.py
```

Файли завантажень і `data/open_training.sqlite3` локальні та виключені з Git. Побудовник оновлює `content/source_registry.json` і `content/dataset_report.json`; перевіряйте в них SHA-256, дату, кількість записів, ліцензійні обмеження, невідомі рівні та дублікати після кожного оновлення. Перед перебудовою зупиніть бота. Не вмикайте CEFR-SP у комерційному розгортанні: його CC BY-NC-SA 4.0 допускає лише некомерційне використання. Open English WordNet потребує збереження атрибуції та повідомлень Princeton WordNet; Octanove — атрибуції та share-alike для похідних матеріалів.

Дані WordNet не містять українських перекладів, а більшість згенерованих з них вправ не має підтвердженого CEFR-рівня. Не змінюйте позначку `unknown` на рівень учня. Нові теми та уроки редагуйте у `content/courses.json`, задавайте точний рівень кожного уроку/вправи та перевіряйте його через `--check`. Відео додавайте лише з підтвердженим URL, автором/каналом і датою перевірки; відсутність відео позначайте як відсутність, не заповнювачем випадкового посилання.

## Навігація, курс часів і YouTube

Головна панель налаштовується в коді бота; вона веде до нового матеріалу, завершених уроків, журналу складних слів, курсу часів, практики, каталогу відео, прогресу й налаштувань. Активні заняття та прогрес окремих курсів зберігаються в `data/bot.sqlite3`. Міграції схеми запускаються автоматично під час ініціалізації БД. Не видаляйте цю базу для оновлення коду.

Курс часів міститься у `content/english_tenses.json`. Це оригінальний внутрішній навчальний матеріал, не офіційна програма CEFR чи НМТ/ЗНО. Перевірте структуру й відповіді через `python -m telegram_bot.main --check`; прогрес часу зберігається окремо від прогресу звичайних курсних уроків.

Каталог `content/youtube_videos.json` містить по одному відео для кожного рівня A1–C2. Перегляд відео фільтрується за рівнем учня, а не за напрямом курсу. Для додавання відео внесіть об'єкт із полями `id`, `title`, `channel`, `url`, `level`, `topic`, `language`, `checked_on`, наприклад:

```json
[
  {
    "id": "a1-example",
    "title": "Назва перевіреного відео",
    "channel": "Назва каналу",
    "url": "https://www.youtube.com/watch?v=VIDEO_ID",
    "level": "A1",
    "topic": "Тема уроку",
    "language": "uk",
    "checked_on": "2026-01-30"
  }
]
```

Усі значення вище — заповнювачі структури, а не підтверджений запис. Для кожного нового відео вручну відкрийте конкретну сторінку YouTube, звірте її назву й канал, оцініть відповідність теми та рівня, а також мову аудіо. Рівень у каталозі є редакторською рекомендацією, якщо сам автор не надає явної CEFR-позначки; це не офіційна сертифікація. Дата `checked_on` — дата фактичної перевірки у форматі `YYYY-MM-DD`; її потрібно оновлювати після повторної перевірки. Підтримуються лише прямі HTTPS-посилання `youtube.com/watch?v=...` або `youtu.be/...`; URL пошуку, сторонніх сайтів, повторні ID та дублікати URL відхиляються. Бот лише показує посилання, не завантажує відео. Якщо для рівня немає записів, учень побачить «Для рівня … відео поки не додано».

Поточні шість посилань додано 08.11.2026. Заголовки та канали звірено з метаданими конкретних роликів через YouTube oEmbed; їхній фактичний аудіовміст окремо вручну не переглядався. Тому мовну позначку та рівень у наявних записах слід вважати попередньою редакторською класифікацією й повторно звірити перед широким використанням. Посилання ведуть на сторінки YouTube; права на відео залишаються у їхніх авторів, бот не копіює й не завантажує матеріали.

У `content/courses.json` загальний курс тепер має уроки A1–C2: до наявних рівнів додано по одному вступному уроку B1, B2, C1 і C2. У бізнес-курсі додано вступні уроки C1 і C2. Це навчальні матеріали проєкту, а не офіційна програма CEFR чи НМТ/ЗНО. Перевірте цілісність курсів і каталогу командою `python -m telegram_bot.main --check`.

Помилки учнів зберігаються окремо від тексту повних повідомлень. Складне слово лишається активним до трьох правильних відповідей, зроблених з інтервалом не менше 20 годин; нова помилка скидає цей streak. Учень може переглянути історію або очистити свій журнал у налаштуваннях; власник не має спеціальної команди для перегляду чужої особистої статистики.

## Профіль LingoPilot і приватний доступ

Тексти профілю та ID бота зберігаються у `content/bot_profile.json`. Скрипт `scripts/configure_bot_profile.py` використовує наявний `BOT_TOKEN` із `.env`, спершу звіряє ID бота й лише після збігу задає назву, About, опис та список команд. Він не виводить і не записує токен. Запустіть із кореневої теки:

```powershell
.\.venv312\Scripts\python.exe scripts\configure_bot_profile.py
```

Ліміти Telegram: назва — до 64 символів, About — до 120, опис — до 512. Актуальні тексти містяться в JSON; скрипт повторно застосовує їх без ручного копіювання. Команди через Bot API виставляються лише для приватних чатів, а стандартний і груповий списки команд видаляються.

Bot API не має методу для завантаження фото профілю чи вимкнення можливості додавати бота до груп. Це потрібно зробити власнику через `@BotFather`:

1. Відкрийте `@BotFather` → `/mybots` → виберіть LingoPilot (переконайтеся, що це потрібний бот; username не змінюйте).
2. **Edit Bot → Edit Botpic** і надішліть `assets/lingopilot-icon.png` (512×512 PNG). Або використайте `/setuserpic` і виберіть цього бота.
3. **Bot Settings → Allow Groups → Turn off** (або `/setjoingroups`) і виберіть вимкнення. Це прибере штатне додавання бота до груп. Якщо бот уже був доданий до групи, видаліть його звідти окремо.
4. Перевірте **Bot Settings → Inline Mode**; якщо ввімкнено, вимкніть через `/setinline`. Проєкт не реєструє inline-query функцій, але BotFather може показувати їх як окрему можливість.

Бот додатково відхиляє повідомлення й кнопки з групових чатів до виконання команд або доступу до БД; дописи каналів отримують лише коротке повідомлення-відмову. Це програмний захист, а не заміна BotFather. Код не змінює чужі чати й не надсилає власницьких запрошень.

## Обов'язки перед наданням доступу

1. Перевірте `ALLOWED_USER_IDS`; обмежте доступ очікуваними учасниками тестування.
2. Перевірте, що актуальний токен зберігається лише в `.env`. Якщо він був оприлюднений — відкличте його у BotFather і замініть.
3. Визначте, хто отримує звернення підтримки, і заповніть `SUPPORT_ADMIN_IDS`.
4. Переконайтеся, що тексти приватності й контакт власника не залишилися заповнювачами; не збирайте непотрібні чутливі дані.
5. Перевірте курси та відповіді вправ перед показом іншим.
6. Вирішіть, чи вмикати резервні копії, хто має доступ до них і коли вони видаляються.

Профілі неактивних учасників і технічні події очищуються при старті та приблизно щодоби. `/delete_me` видаляє профіль і пов'язані записи з активної бази; окремі резервні копії потребують окремого видалення.
