# Технічна документація та посібник підтримки

## 1. Огляд системи

LingoPilot — Telegram-бот на Python 3.12+ з aiogram 3. Він працює як локальний процес із long polling: бот опитує Telegram Bot API за вихідним HTTPS-з'єднанням. HTTP-сервер/webhook для поточного запуску не використовується. Розміщення в Telegram не означає, що код або база зберігаються в Telegram: процес і SQLite-файли лежать на комп'ютері адміністратора.

Основні компоненти:

- `telegram_bot/main.py` — CLI, завантаження налаштувань, старт polling, нагадувань, перевірки та створення каталогу.
- `telegram_bot/bot.py` — обробники Telegram, onboarding, уроки, повторення, підтримка, модерація та цикл нагадувань.
- `telegram_bot/config.py` — читання `.env` і перевірка конфігурації.
- `telegram_bot/database.py` — SQLite-схема, прогрес, версії курсів, retention.
- `telegram_bot/content.py` — валідація курсу й відеопосилань.
- `telegram_bot/logic.py` — оцінювання рівня, план навчання, повторення, часові зони й інтервали.
- `content/courses.json` — початковий матеріал двох курсів.
- `content/vocabulary_bank.json` і `scripts/build_course_catalog.py` — вихідний словник і генератор додаткових каталожних уроків.

## 2. Життєвий цикл процесу

1. `start_bot.ps1` перевіряє наявність `.env`, непорожнього `BOT_TOKEN` і `.venv312` з Python 3.12+.
2. `telegram_bot.main` читає змінні середовища; токен є обов'язковим лише для звичайного запуску.
3. Створюється SQLite-база й перевіряються міграції схеми.
4. Файл курсів проходить валідацію; початкові версії додаються лише за відсутності відповідного ID курсу в БД.
5. Виконується очищення прострочених профілів і технічних подій.
6. Реєструються команди Telegram, запускається `reminder_worker` та aiogram long polling.
7. Під час завершення polling worker скасовується, Telegram-сесія закривається.

Для приватного тесту налаштуйте `ALLOWED_USER_IDS`. Порожній список означає відсутність глобального ID-фільтра; це не є приватним доступом.

## 3. Потік користувача

`/start` створює профіль і показує повідомлення про приватність. Після підтвердження користувач обирає опублікований курс, відповідає на питання тесту, підтверджує або вручну задає рівень, обирає темп і розклад нагадувань. Поточний крок і службові дані кроку зберігаються у `users.state` та `users.state_data_json`.

Уроки та відповіді доступні за клавіатурами Telegram. Відповіді фіксуються в таблиці спроб; пропуск завершує вправу без відповіді. Слова додаються до інтервалу повторень. `/continue` орієнтується на активний крок користувача, заплановані повторення та наступний незавершений урок. Прогрес рахується для вибраного курсу; серія навчання використовує локальні дні.

## 4. Ролі та авторизація

- `ALLOWED_USER_IDS` — зовнішній middleware на повідомленнях і callback-запитах. Якщо список непорожній, усі інші ID отримують відмову до виклику бізнес-обробника.
- `MODERATOR_IDS` — окрема перевірка в кожній команді адміністрації контенту.
- `SUPPORT_ADMIN_IDS` — одержувачі тексту звернення `/support`; це не адміністративна команда й не список модераторів.
- Власник операційно керує `.env`, BotFather, запуском процесу, файлами БД, журналами та резервними копіями.

Усі ID задаються як десяткові цілі числа через кому. Якщо треба надати іншим користувачам доступ до обмеженого тесту, додайте їх у `ALLOWED_USER_IDS` і перезапустіть процес. Не передавайте BotFather-токен модераторам чи тестувальникам.

## 5. SQLite та збереження даних

Стандартний файл — `data/bot.sqlite3`. У ньому зберігаються:

| Таблиця | Призначення |
|---|---|
| `users` | Telegram ID, згода, вибраний курс і рівень, темп, розклад, стан діалогу, остання активність. |
| `course_versions` | JSON курсу, номер версії та статус `pending`/`published`. |
| `lesson_catalog`, `vocabulary_catalog`, `exercise_catalog` | Нормалізовані дані курсу для SQL-огляду. |
| `vocabulary_progress`, `lesson_progress`, `study_activity` | Інтервали повторення, завершення уроків і навчальні дні. |
| `exercise_attempts` | Правильність відповіді й час спроби; текст повідомлення користувача не зберігається в цій таблиці. |
| `notification_log` | Статуси нагадувань і захист від повторної відправки за день. |
| `technical_events` | Короткий тип технічної події й час, без тексту повідомлень. |
| `schema_migrations` | Застосовані версії схеми. |

Таблиці прогресу мають зовнішні ключі з каскадним видаленням за профілем. `--init-content-db` створює окремий файл `data/course_catalog.sqlite3` для перегляду курсів і не містить профілів тестувальників.

## 6. Модерація контенту

Модератор надсилає JSON-документ і reply-команду `/admin_import`. Бот обмежує файл 256 000 байтами, декодує UTF-8, парсить JSON і виконує `validate_course`. Валідний курс зберігається як наступна версія `pending`, попередній опублікований курс не замінюється. `/admin_pending` виводить ID і номер чернетки; `/admin_approve id:version` публікує її.

Валідація перевіряє обов'язкові поля, `en`, дозволені треки, CEFR-рівні, непорожні описи, унікальність ID, порядок уроків, питання тесту, вправи й HTTPS-URL відео. Вона не перевіряє фактичну правильність англійської, якість перекладу, авторські права чи відповідність методиці — це редакторська відповідальність.

Генератор каталогу — окрема офлайн-команда `python -m scripts.build_course_catalog`. Він будує уроки з `content/vocabulary_bank.json` і перезаписує джерело `content/courses.json`; запускати його слід лише після перевірки diff/результату й збереження редакторських змін. Звичайний запуск бота не запускає цей генератор.

## 7. Нагадування і retention

`reminder_worker` перевіряє розклад користувача відповідно до IANA-часового поясу й вибраних днів. Для запобігання дублям спершу додається запис у `notification_log`; успіх/помилка оновлюють його статус. Якщо користувач заблокував бота, нагадування автоматично вимикаються. Часова зона й доступність процесу впливають на доставку.

Стандартна конфігурація — `INACTIVE_PROFILE_MONTHS=12`, `TECHNICAL_LOG_RETENTION_DAYS=30`. Очищення запускається при старті й раз на день. Файлові логи обертаються щодня; строк ротації задається retention-значенням (кількістю резервних файлів). Ці строки треба підтвердити власнику перед публічним використанням. Резервні копії файлів не очищуються кодом автоматично.

## 8. Журнали та діагностика

Логи йдуть у консоль і `logs/bot.log`; токен не слід додавати в діагностичний звіт. Текст `/support` пересилається адміністраторам підтримки й не пишеться в звичайні application logs. Успішне звернення не зберігається як повідомлення в SQLite; невдала доставка реєструє лише тип технічної події.

| Симптом | Що перевірити |
|---|---|
| `BOT_TOKEN is empty in .env` | Відкрийте саме `.env`, перевірте `BOT_TOKEN=...`, збережіть файл. Токен не повинен бути в `.env.example`. |
| `ModuleNotFoundError: aiogram` | Запустіть `.\.venv312\Scripts\python.exe -m pip install -e ".[dev]"`; перевірте мережу та доступ до PyPI. |
| `Failed to fetch updates` / `Server disconnected` | Тимчасовий збій мережі/API може автоматично повторюватись. Переконайтеся, що інтернет працює й процес не завершений; перевірте токен. |
| `Conflict: terminated by other getUpdates request` | Інший процес з тим самим токеном уже виконує polling. Зупиніть зайву копію; для одного токена залиште один polling-процес. |
| Бот мовчить лише для окремого користувача | Перевірте точне значення `ALLOWED_USER_IDS`, числовий Telegram ID та перезапустіть процес після зміни `.env`. |
| Модератору відмовлено | Перевірте ID в `MODERATOR_IDS`; це інше налаштування, ніж `ALLOWED_USER_IDS`. |
| `/support` не працює | Перевірте `SUPPORT_ADMIN_IDS`, факт запуску `/start` і можливість бота написати адміністраторам; адресати мають відкрити бота першими. |
| Чернетка не знаходиться | Виконайте `/admin_pending` і використайте точну пару `course_id:version`. |
| База не створюється | Переконайтеся, що шлях доступний для запису, каталог не зайнятий/заблокований, і подивіться повний traceback у консолі. |

Для повідомлення про проблему запишіть час, команду/крок, версію Python, тип мережі та очищений traceback. Не надсилайте `.env`, токен, повний Telegram ID користувача або особистий текст підтримки. Не вважайте одиничний `ServerDisconnectedError` доказом неправильного токена.

## 9. Резервне копіювання і відновлення

Перед ручним резервним копіюванням зупиніть процес бота. Скопіюйте `data/bot.sqlite3` у сховище з обмеженим доступом і визначеним строком видалення. Не завантажуйте базу з реальними профілями у відкриті хмари чи публічний репозиторій. Відновлення спершу перевіряйте на копії файлу; після відновлення перевірте профілі, прогрес і активні версії курсів. Якщо файл SQLite має WAL/SHM-супутники, зупинка процесу перед копіюванням допомагає уникнути неповної копії.

`/delete_me` видаляє запис профілю та пов'язані з ним записи активної БД. Переконайтеся, що процедури резервних копій дозволяють виконати окремі запити на видалення або очищення копій у визначений термін.

## 10. Перевірки та випуск

З кореня проєкту у Windows:

```powershell
.\.venv312\Scripts\python.exe -m pytest
.\.venv312\Scripts\python.exe -m compileall -q telegram_bot tests scripts
.\.venv312\Scripts\python.exe -m telegram_bot.main --check
```

Перед оновленням перевірте тести, diff контенту й конфігурації. Не замінюйте `data/bot.sqlite3` під час оновлення коду. Для реального Telegram smoke test використовуйте актуальний секрет, один процес polling і контрольований allowlist.

## 11. Відомі межі

- Поточне розміщення локальне; вимкнений/сплячий комп'ютер зупиняє відповіді й нагадування.
- Доступ до Telegram з іншого облікового запису можливий, якщо він дозволений `ALLOWED_USER_IDS` або глобальний allowlist порожній.
- Рівень і відсотки прогресу орієнтовні, а не сертифікація.
- Структурна валідація не замінює мовного, методичного й правового review контенту.
- Частина прикладів для каталожних слів створюється за шаблонами генератора; перед використанням у навчанні їх варто перевірити на природність і точність перекладу.
- Курсова версія, що завантажена командою модератора, зберігається як чернетка до затвердження.
- Політика приватності містить поля для заповнення; її потрібно узгодити з фактичним використанням і не трактувати як юридичну гарантію.
